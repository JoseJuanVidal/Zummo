API Solicitud de alta de productos

Servicio web de Business Central para crear solicitudes de alta desde el PDM · Extensión Zummo 1.0.0.1018 · octubre 2026

Qué hace

Permite que el PDM (o cualquier otra aplicación) cree en Business Central una solicitud de alta de producto, la misma que se crea a mano en Solicitud Alta de productos, y opcionalmente la lance al departamento de planificación.

Al recibir el Nº de producto, BC busca su plano en el PDM y rellena los campos que no se hayan enviado: descripción, traducciones, motivo, material, peso y "sustituye a". Lo que se envía en la llamada siempre prevalece.

Operaciones

OperaciónUso
POST …/SolicitudAltaProductosCrea una solicitud. BC asigna el número (SOL26xxxx) y lo devuelve en No.
GET …/SolicitudAltaProductos('SOL260138')Lee una solicitud. También se puede filtrar: ?$filter=Item_No eq '260525B'.
PATCH …/SolicitudAltaProductos('SOL260138')Modifica una solicitud. Cabecera If-Match con el @odata.etag leído (o *). Sirve, por ejemplo, para lanzarla después con {"Lanzado": true}.
La API solo muestra solicitudes en estado vacío o Solicitado. Cuando planificación la pasa a revisión de departamentos ya no se ve ni se puede modificar desde la API.

Qué hace BC al crear la solicitud

  1. Asigna el número de solicitud, la fecha de registro (si no se envía), el usuario (User_ID) y el empleado del usuario de la llamada.
  2. Aplica las validaciones del tipo de solicitud (por defecto New): en un alta nueva el producto no debe existir; en un cambio, carga los datos del producto existente.
  3. Busca el plano del PDM: por PDM_Document_ID si se envía; si no, por Item_No (código exacto, o el código -X del PDM para variantes de color: 250502B-18 → 250502B-X). Informa PDM_Status.
  4. Si encuentra el plano, rellena los campos vacíos con los datos de su última versión (aprobada o no):
    • Description, TranslateENG, TranslateFRA y Reason (texto "Modificación" del PDM);
    • Material, Net_Weight y Gross_Weight de la pieza (SLDPRT) del mismo código; el PDM da la masa en gramos y se guarda en kg;
    • Replaces_Item_No (solo en altas nuevas): el código aprobado anterior del mismo plano, si existe como producto (260525B → 260525A; con colores, 250510B-18 → 250510A-18).
  5. Guarda los datos enviados, que prevalecen sobre los del PDM.
  6. Si Lanzado = true, la lanza (ver más abajo).

Lanzar la solicitud (Lanzado)

Con "Lanzado": true BC hace lo mismo que la acción Solicitud Alta/Actualización de la ficha: comprueba los datos, envía el email al departamento de planificación (altas@zummo.es) y deja la solicitud en estado Solicitado. Desde la API no se piden las confirmaciones que salen en pantalla.

Para lanzar hace falta:

  • Reason informado (enviado o tomado del PDM);
  • Request_Type distinto de vacío (por defecto New);
  • Purch_Family, Purch_Category y Purch_SubCategory (campos obligatorios configurados para el solicitante).

Si falta algo, la llamada devuelve el error y no se crea nada (todo o nada). Para crear primero y lanzar después, hacer el POST sin Lanzado y luego un PATCH con {"Lanzado": true}.

Si el plano del PDM no está aprobado, en pantalla se avisa al lanzar; desde la API no se bloquea: el estado queda en PDM_Status y la solicitud se relacionará sola con el plano cuando se apruebe.
